Правила проектирования (Rules & Guidelines) для вашей документации
Чтобы ваша команда разработчиков и безопасников понимала, как обслуживать эту систему, внесите в документацию следующие обязательные регламенты:

Правило нулевого доверия к данным (Zero-Trust Data Ingestion):

Все документы перед нарезкой на чанки должны проходить автоматический аудит на наличие паролей, токенов, ключей API и жестких PII-данных.

Метаданные каждого чанка обязательно должны содержать поле allowed_roles (список отделов или ролей, имеющих доступ). Запрещено индексировать документы без указания прав доступа.

Правило изоляции контура (Air-Gapped Deployment):

Запрещено использовать любые внешние платные API (OpenAI, Anthropic, Pinecone Cloud). Все компоненты (векторная база, модель эмбеддингов, LLM) должны развертываться внутри закрытого Kubernetes-кластера компании с выключенным внешним интернетом для подов инференса.

Регламент аудита и логирования (Audit Trail):

Каждый запуск пайплайна (EnterpriseRAGPipeline.run) должен логировать в защищенное хранилище:

Хэш-суммму запроса пользователя (без сохранения персональных данных в открытом виде).

Список идентификаторов документов (doc_id), которые были реально извлечены и переданы в промт.

Метрику задержки (Latency) каждого этапа (эмбеддинг, поиск, генерация).
